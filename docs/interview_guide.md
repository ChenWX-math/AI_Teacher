# AI 智能教师：简历与面试表达

## 简历项目描述

**AI 智能教师｜LangChain Agent + RAG + Milvus Lite**

- 基于 LangChain 1.x 构建多学科教学 Agent，将教材检索、练习生成和答案批改封装为结构化工具，由模型自动完成意图路由，并保留经典 Chain 作为故障回退。
- 使用 DashScope Embedding 与 Milvus Lite 构建 9 学科教材知识库，实现带学科过滤、相关度和原文片段的可解释 RAG；42 条检索集达到 Recall@3 100%、MRR 0.988。
- 将聊天历史与教学任务状态分离，实现“讲解—出题—作答—批改”多轮闭环；通过较早摘要、最近原文和结构化状态控制长上下文。
- 建立 pytest、Ruff、GitHub Actions、真实模型离线评测与脱敏 JSONL 日志，使外部 API 测试显式触发、免费回归测试可在 CI 稳定执行。

## 2～3 分钟讲解稿

这个项目最初是一个固定 RAG Chain：学生提问后，由用户手动决定是否查教材。它能运行，但有三个明显问题：系统不会根据教学意图采取不同动作，检索效果没有量化，多轮出题和批改也容易丢失上下文。

我先做了工程基线，把配置、模型、会话和 RAG 模块拆开，并补上免费单元测试。随后建立 9 个学科、42 条问题的检索评测，使用 Recall@K、MRR 和关键词覆盖率验证 Milvus 检索，同时把实际使用的教材来源展示给用户。

第三步是 Agent 化。我把教材检索、出题和批改定义为带 Pydantic Schema 的工具，并为工具选择建立真实模型评测。第一版只有 6/9，原因是工具描述存在重叠；我增加明确优先级和必须调用规则后通过全部用例。结构化生成方面，我发现自由 JSON 会改字段名，因此改为 Function Calling 和 strict Schema。

为了支持连续教学，我没有把所有信息都塞进聊天历史，而是单独保存当前知识点、练习、隐藏参考答案和最近批改。长对话使用“较早摘要 + 最近原文 + 结构化状态”，摘要失败时回退到有 Token 上限的滑动窗口，所以重要题目状态不会只存在于有损摘要里。

最后，我加入 GitHub Actions、结构化脱敏日志和 36 条 Agent 评测，记录工具选择、参数有效性、任务完成、引用约束、平均/P95 延迟及 Token。这个项目体现的不只是调用框架，还包括 RAG 评测、Agent 轨迹、状态边界、失败回退和工程交付。

## 高频追问答题要点

### 为什么 Agent 比固定 RAG Chain 更合适？

固定 Chain 每次执行同一路径，容易对寒暄也检索、对答案提交也只做问答。Agent 根据意图选择零个或一个必要工具，更符合教学场景；经典 Chain 仍保留为回退。

### 为什么聊天历史和教学状态要分开？

聊天历史适合语言上下文，但会被裁剪或摘要；当前题目、参考答案等属于不能有损的业务状态。分开后可以独立验证、跨轮读取、按会话隔离，并避免参考答案暴露给主 Agent。

### 如何证明 RAG 有效？

检索层用 Recall@1/3、MRR、关键词覆盖率；回答层展示引用并检查引用编号是否合法。当前忠实度是执行轨迹代理，尚不能替代人工评审或校准后的 LLM-as-a-Judge。

### 怎样控制成本和延迟？

教材库按需加载，工具按意图调用，历史超过预算才摘要；评测同时记录平均和 P95 延迟、输入输出 Token，并允许按供应商当前单价计算估算成本。

### 如果换模型怎样避免静默回归？

先运行免费 pytest 和 CI，再显式运行真实模型路由评测，比较工具选择、参数有效率、任务完成率、延迟和 Token；任何失败样本先进入回归集再修复。
